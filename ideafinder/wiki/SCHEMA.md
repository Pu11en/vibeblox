# Wiki Schema

## Domain

Repo category map for GITBUTT: every GitHub repo in the pool (from the
@GithubAwesome channel) classified into a taxonomy of categories, so the idea
bot can think in terms of the landscape instead of raw repo names.

## Conventions

- Source of truth: the SQLite database (`data/repos.sqlite3`). Pages are
  machine-generated and regenerated by `uv run gitbutt wiki`.
- File names: lowercase, hyphens, no spaces.
- Every page starts with YAML frontmatter (title, created, updated, type,
  tags, sources).
- Category pages live in `concepts/` and use `[[wikilinks]]` to related
  categories (minimum 2 outbound links per page).
- Every wiki action is appended to `log.md`. Every page is listed in
  `index.md`.
- Repo summaries quoted on category pages come from `repo_summaries`
  (DeepSeek + README excerpts; early rows derived from video transcripts),
  truncated; the DB holds the full text.

## Tag Taxonomy

Tags are the category names from `data/taxonomy.json`. The classifier only
ever assigns categories present in the taxonomy. To add a category, add it to
the taxonomy and re-run `uv run gitbutt wiki`.

## Page Thresholds

- One page per category that has at least one repo.
- No entity pages per repo: 1,300+ repos would drown the wiki. Repos are
  bullets on their category page.
- Split a page when it exceeds 200 lines.

## Update Policy

Pages are regenerated on every `wiki` run. Never edit pages by hand; edit the
pipeline (or the taxonomy) and regenerate.
