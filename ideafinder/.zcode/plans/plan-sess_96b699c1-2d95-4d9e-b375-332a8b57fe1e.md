## Part 4 — The plugin (new)

10. **Manifest** `.zcode-plugin/plugin.json`: name `gitbutt`, version 0.1.0, description, `"skills": "./skills"`, `"mcpServers"` with one stdio server launched via the project venv python (`-m gitbutt.mcp`, cwd = plugin root, `PYTHONPATH` neutralized against Hermes pollution, `.env` auto-loaded by existing code).
11. **MCP server** `src/gitbutt/mcp.py` (adds the `mcp` Python SDK dependency). Tools, all driven by you in natural language:
    - `status()` — repo/idea counts, last scrape, missing summaries
    - `scrape_new()` — fetch new @GithubAwesome videos from RSS, extract repos (the "find the most recent videos" flow)
    - `summarize_missing(limit)` — DeepSeek + README summaries for repos that lack them
    - `search_repos(query, limit)` — keyword/tag/category search with summaries → the "find repos that help my current project" flow
    - `build_ideas(theme, count)` — themed product ideas (one or two repos glued into a pitched concept; no theme = landscape pick) — the core "make stuff" mode
    - `landscape(topic)` — category briefing: who's building what, gaps
    - `spotlight(repo)` — deep dive on one repo: what it does, who it's for, what you could build with it
    - `digest(limit)` — fresh picks: most recently scraped repos you haven't seen
    - `rank_ideas(limit)` — the existing money scoring (rank + tier2), on demand
    Reuses existing modules (scrape, summaries, ideas, ranking, tier2, categories); no new schema changes to repos.sqlite3.
12. **Skill** `skills/gitbutt/SKILL.md` — teaches me in a session: what the plugin is, the tools above and when to use them, data locations, and safety rules (never run scrape/summarize just to inspect — they hit the network and mutate the DB; never print `.env`; keep SQLite connections short; channel-brains is now unrelated).
