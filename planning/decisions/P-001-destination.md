# P-001 — Destination: what game are we building?

**Status:** current (planning)
**Depends on:** none

## Decision

The destination of this plan: which game shape we plan to build. This decides
scope, route, proof, and every downstream ticket.

## Context (confirmed so far, from conversation)

- The loop is proven locally: click-to-plan tycoon → factory → DeepSeek brain
  → real public GitHub repo (live example: Pu11en/play2build-snake-game-3f7a).
- Drew wants plan-first, build-once: a very precise plan, then a one-shot
  build. Planning is the main activity of this session.
- Ideas have been discussed: built-in idea cards today; the repo-idealab
  YouTube channel as a future idea feed ("the game becomes a plugin for that
  channel, ideas always coming").
- The public game (players, Robux→credits economy, GitHub connect) is the
  long-standing North Star, deliberately out of the validation scope.
- Hard UX requirements (from the closed wayfinder map): clicking, not typing;
  A/B/C multiple-choice interaction; caveman-simple language; "feels like
  play, not work".

## Viable options

- A. **Private polished game** — make the current single-player tycoon the
  best version of itself (feel, fun, quality repos). Smallest scope; playable
  soon; the foundation the other options build on.
- B. **Public game** — players, credits economy, GitHub account linking. The
  North Star; largest scope; needs policy care (Robux↔real-world value).
- C. **Channel plugin** — repo-idealab's repos become the game's idea feed;
  the game becomes the channel's interactive front end. Ties the game to the
  YouTube channel; medium scope; ideas always fresh.

Options can combine (e.g., A now, C next, B later) — the plan's map should
reflect the staged route once the destination is chosen.
