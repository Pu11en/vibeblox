# What counts as "it works"?

> `wayfinder:grilling` — child ticket of the map. Created 2026-08-02.
> **CLOSED 2026-08-14** — bar set (and the build handoff already meets it).

## Resolution

The destination is **validated when**: Drew plays one full round in Studio —
picks an idea, answers the three questions, watches the workers — and a
**real, public repo** (`play2build-*`, real generated code, runnable) appears
on his GitHub, then Drew says the round **felt like play** (vibe check
during the session: did he click through a backend admin panel, or play a
game?). That single playthrough is the exit criterion.

Supporting bars:

- **The repo:** real code generated by the engine (not stubs); backend
  syntax-checks it before push (py_compile / node --check, one auto-fix
  retry) — CI-green is approximated by the local check for v0.1. Drew
  verifies by opening the repo link the game shows.
- **Repetition:** one success proves the loop; a second round with a
  different idea proves it isn't a fluke. Variety beyond that is v1.
- **Feel:** no typing anywhere; every action is a click; all text
  elementary; the plan summary reads like a 10-year-old wrote it. Drew
  rates it by feel at the end of the round.
- **Cost & latency:** per-run cost must be visible (backend tracks it —
  DeepSeek v4-flash, fractions of a cent per small project); latency budget
  ~2-3 minutes for a small project (plan → repo link). If a build drags
  past ~3 minutes for "Tiny", the loop fails the patience budget.

Everything above is met by the v0.1 build (`play2build/`) pending Drew's
live playthrough.

## Question

Set the acceptance bar for the whole validation — the destination's "validated" made
concrete:

- **The loop** — how many successful playthroughs (game → backend → agents → real repo on
  Drew's GitHub) count as proven? Any required repetition or variety (different templates)?
- **The repo** — what a "real" test repo must contain (real code generated by the engine,
  not stubs), and how Drew verifies it.
- **The feel** — how "feels like play, not work" gets judged (one playthrough rated by Drew?
  a checklist? a vibe check during the session?).
- **Cost & latency** — the per-run ceiling and the patience budget (how long a playthrough
  may take before it stops feeling like play).

The answer becomes the map's exit criteria — the bar the future build handoff must meet.
